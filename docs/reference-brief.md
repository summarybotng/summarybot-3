# SummaryBot-NG Rust/WASM Rewrite — Implementer Reference Brief

This brief surfaces what `docs/PRD.md` does NOT tell you: the reasoning behind committed requirements, traps the original implementation fell into, and decisions buried in ~100 ADRs. Read this alongside the PRD before writing any code.

> Generated by an ADR/tech-debt synthesis workflow over `/workspaces/summarybot-ng-reference` (19 deep ADR reads + 115-entry catalog + technical-debt.md + PRD diff). Sources are reference-only; re-derive for Rust.

## TL;DR

- **The product pivoted.** This is no longer a Discord bot — it is a multi-tenant, multi-platform workspace platform. `guild_id` → `workspace_id` everywhere, with an orthogonal `tenant_id` layer. Design the data model workspace/tenant-first from day one; do not bolt Discord assumptions into the core (ADR-066, ADR-079; PRD §2.4, §6.3, §7.1).
- **Hallucination prevention is now a hard requirement, not a "nice-to-have."** The Coherence Gate (COH-001) was promoted from Medium/Future to HIGH/Committed. RuVector is the committed knowledge store, but only Phase 1 + Coherence Gate are in scope — agent memory, SONA, and rvLite remain future (ADR-052, ADR-057, ADR-087, ADR-090).
- **Summary generation is a resilient retry pipeline, not a single LLM call.** Up to 7 attempts, model escalation (Haiku→Sonnet→Sonnet-4→Sonnet-4.5), failure-type-differentiated strategies, and a hard $0.50 cost cap. Get this architecture right early — it touches SUM-001/002/011/012 (ADR-024, ADR-025, ADR-022, ADR-023, ADR-095).
- **Citations are structural, not cosmetic.** Every summary claim carries ≥1 message reference via position-number indexing resolved post-parse. The schema and parser must be versioned together or citations silently break (ADR-004; SUM-009).
- **The original codebase died of monolithic route files and in-memory state.** 5,574-line route files, in-memory job/session/event stores deployed to prod, 36% test coverage. The rewrite mandate: thin handlers → service layer → repositories, no file >500 lines, zero in-memory state in handlers, persistent everything.
- **Scope is dynamic and runtime-resolved.** Channel/category/guild scope resolves at execution time (new channels auto-included), and titles reflect channels-with-content, not requested scope. This affects scheduled, rolling, and retrospective summaries (ADR-011, ADR-098, ADR-101).
- **Many "implemented" features were stubs.** Webhooks, email delivery, Confluence export, Google Drive sync, Vault, LLM synthesis all shipped DB schema before working code. Treat schema-before-implementation as an anti-pattern; "done" = survives restart with correct semantics.
- **Identity must be pluggable.** Discord-only login blocked everything. Ship ≥2 identity providers (e.g., Discord + email/Google) to validate the abstraction (WSP-001; ADR-049, ADR-066).

## Critical design decisions (from ADRs)

### Summarization
- **Grounded references (ADR-004 → SUM-009).** Decision: embed message-level citations in every structured element. Non-obvious: Claude cites compact position numbers `[N]` (1-based) in the prompt; a `PositionIndex` resolves them to full `MessageReference` objects post-parse, so the model never handles verbose metadata. Dedup references via `HashMap<message_id, MessageReference>` (O(n²) struct comparison kills >500-msg conversations). Citations to nonexistent positions are silently dropped + logged — no hard fail. API defaults: `references=false` for Discord legacy, `true` for new endpoints. Schema and `SummaryResult` MUST be versioned together.
- **Resilient multi-model retry (ADR-024 Accepted, ADR-025 Proposed — overlapping/duplicate; treat ADR-024 as canonical → SUM-001/002/011/012).** Decision: ≤7 attempts, fixed 6-model escalation chain, $0.50 hard cap. Non-obvious: starting model index is *summary-type-dependent* (brief=Haiku idx 0, detailed=Sonnet idx 2, comprehensive=Sonnet-4 idx 4), NOT tier-agnostic. Failure handling differs by type: truncation → double max_tokens (cap 16K) *then* escalate; JSON parse error → JSON-reminder prompt first; malformed content → immediate escalation; network/timeout → same model + backoff; rate limit (429) → respect `retry_after`, same model. Cost cap is a hard ceiling that halts mid-chain (can leave a request with NO final summary). Quality detection keys off fragile markers like `[Unable to parse...]` and `stop_reason == max_tokens`.
- **Truncation & JSON recovery (ADR-022, ADR-023).** Auto-retry truncated responses with escalated tokens; hybrid JSON recovery = repair library → retry-with-reminder → freeform fallback. These are subsumed by the ADR-024 pipeline.
- **Adaptive token allocation (ADR-095 → SUM-015/002/011).** Decision: scale `max_tokens` = `(input_chars/4) / compression_ratio`, clamped. Non-obvious: ratios are Brief 4:1, Detailed/Comprehensive **1:1** — weekly guild-wide summaries are ~1:1 not 10:1 because the model itemizes per-channel. Use integer/fixed-point math for the cost cap, not floats. v3 ratios came from production data (30-33k char inputs needing 8k+ output).
- **Emergent wiki structure (ADR-090 → SUM-009, SCP-001).** Knowledge units extracted *inline* during summarization (single LLM call, max 20 units/summary), not post-processed. Wiki pages emerge from semantic clusters (Louvain community detection, edge threshold 0.65, min cluster 5 / max 100). Dual-write to summaries + knowledge_units must be atomic.

### Scheduling / Rolling
- **Unified scope selection (ADR-011 → SUM-005/006/008).** Scope (CHANNEL/CATEGORY/GUILD) resolves at execution time. Category scope = ONE combined summary. Store `scope_channel_ids` AND `channels_with_content` separately; titles built from content only. Category summaries can blow token/cost budgets.
- **Rolling period summaries (ADR-101 → ROL-001..006).** Daily accumulation toward weekly/biweekly/monthly finals via Append / Re-summarize-All / Hybrid-Merge strategies. **Critical invariant: exactly one active (non-finalized) rolling summary per schedule** — violations orphan summaries. Catch-up logic must fetch all messages since `accumulated_through`, not just yesterday. Finalization must be idempotent. Model `accumulation_strategy` and period as strong Rust enums.
- **Rolling dedup (ADR-118 → SUM-010).** Three layers: (1) guard clause before extraction, (2) deterministic SHA256 ID over `guild_id:source_id:unit_type:content` (enables `ON CONFLICT` upsert — random UUIDs never dedup), (3) CoherenceGate at 0.95 similarity during *inline* ingestion. Hash key format is load-bearing: changing it invalidates all existing IDs.
- **Per-destination delivery control (ADR-108 → ROL).** Flag controls whether each destination delivers on intermediate runs or finalization only.
- **Traceability (ADR-102, ADR-109).** Bidirectional schedule↔job↔summary links; snapshot schedule metadata so traceability survives schedule deletion (no `ON DELETE CASCADE` orphaning).
- **Unified creation wizard (ADR-089 → SCH-001..004, SCP).** 3-step wizard; Step 2 branches (Now/Past skip delivery; Recurring continues). Continuity toggle only for weekly; interval schedules hide time picker.

### Platform-agnostic
- **Platform-agnostic architecture (ADR-066 → WSP-001..008, AUTH-001..004; PRD §2.4, §7.1).** Workspace IDs are UUIDs; `platform_id` lives in `workspace_connections` (UNIQUE on platform+platform_id). One workspace → multiple platform connections. JWT changes from `sub=discord_user_id, guilds=[]` to `sub=user_uuid, workspaces=[], identities={}`. `PlatformAdapter` trait returns `NormalizedMessage`. **Two unresolved open questions baked into the ADR:** identity-linking collision resolution, and workspace creation strategy (auto vs explicit).
- **Message fetcher abstraction (ADR-051).** Strategy/`PlatformFetcher` pattern centralizing 8+ duplicated branches. Non-obvious: Slack must auto-join on `not_in_channel`; archive keys are platform-prefixed (`discord:123`); Discord supports category scope, Slack does not; `detect_platform()` defaults to `discord` for legacy. Errors collected (partial success), not raised. **Rust caveat: `Protocol` structural typing → `async_trait`; collecting all raw messages before batch processing risks WASM memory limits — prefer streaming.**
- **Platform-agnostic UX (ADR-078 → FUT-001..006).** Workspace/Source terminology; conditionally render Discord-only concepts (voice, categories, member counts). WhatsApp is import-only (no real-time scheduling). Keep `/guilds` routes alive during transition.
- **Source-guild relationship (ADR-085), multi-platform source (ADR-026), Slack feasibility (ADR-043).** Many-to-many Slack linking via junction table; non-Discord sources keyed under primary guild with `archive_source_key`. Slack uses two-tier scope model for private channels.

### Knowledge / RuVector / Wiki
- **RuVector integration vision (ADR-052 → KNO-002/003/005, FUT-016..020; promoted §8.3).** 4 phases; only Phase 1 (semantic search) + Coherence Gate committed. Dual-index with FTS5 in Phase 1 (benchmark in parallel, target <100ms p99). SONA/GNN/rvLite remain future. Coherence Gate prevents learning drift — now COH-001 HIGH.
- **Ingestion granularity (ADR-087 → WIK/KNO/SCP/ROL, SUM-010).** RuVector = primary store; markdown wiki = cached *views*. Granularity is a render-time choice, not ingest-time. Raw messages preferred (summaries lose cross-refs); summaries are fallback beyond API retention. Weekly continuity checkpoints bridge context. **Gotcha: GNN infers `relates_to` but NOT causal intent — causality still needs LLM pre-synthesis. Human markdown edits must feed back as `human_correction` units (confidence=1.0).** Depends on ADR-057 being complete first.
- **Wiki implementations (ADR-056 FTS5, ADR-057 RuVector-enhanced, ADR-060 human+AI curation, ADR-063 dual-tab pages, ADR-067 auto-ingestion, ADR-068 backfill jobs).** Wiki pages have synthesis tab (default) + append-only raw-updates tab for provenance. Auto-ingest after summary storage. Filter ingestion by perspective (ADR-080).
- **AI Wiki Curator (ADR-077 → CUR-001..007, FUT-021..025; promoted §8.4).** 7 skills; confidence-gated approval (>0.9 auto, 0.7-0.9 batch, <0.7 manual). All actions reversible via `rollback_data` JSON. Uses HNSW semantic similarity, not string matching. Scoped per guild/workspace.

### Delivery
- **Destinations (ADR-005 dashboard, ADR-014 Discord threads/templates, ADR-047 Discord DM, ADR-030/032 email, ADR-029/099 Confluence).** Dashboard delivery always-on (core value prop). Confluence (ADR-099, Implemented): service-account auth (no OAuth refresh), AES-256-GCM encrypted `email:api_token`, idempotency via version numbers (reject external mods unless force-update), ADF formatting, local-only labels that don't sync. Date macro uses millisecond timestamps. Bulk publish (ADR-110) needs throttling.
- **Google Drive (ADR-007 per-server sync, ADR-082 import, ADR-091 export config).** Hierarchical config with server OAuth + default fallback. WhatsApp imports via service-account Drive polling (avoids per-user OAuth).

### Jobs
- **Unified job tracking (ADR-013 Implemented → JOB-001..006).** All job types (MANUAL/SCHEDULED/RETROSPECTIVE/REGENERATE) in one table. Non-obvious: on startup, RUNNING jobs → PAUSED reason `server_restart` (prevents orphans). Job record created *synchronously before* async work. Errors persisted, not just logged. Keep last 50 jobs. **Known debt: retry creates a record but does NOT auto-execute (manual click required); no failure classification; no backoff.**
- **Intelligent retry (ADR-042) + self-healing validation (ADR-038).** Classify failures (transient/resource/recoverable/persistent/code-error); auto-retry only transient. Self-healing validation has an audit trail of fallbacks — but see debt: silent fallbacks are an anti-pattern to fix.

## Technical debt — what to avoid

- **No God files.** Original had route files of 5,574 / 4,051 / 2,277 lines with 46+ endpoints each. Hard rule: no source file >500 lines. Thin handler → service → repository. Business logic NEVER in handlers.
- **No in-memory state in handlers.** `_generation_tasks: dict`, in-memory sessions, in-memory event queues were deployed to prod and lost on restart. Use DB-backed task tracking, DB-backed sessions, and a real message queue from day one. In WASM, treat all state as loaded-from-storage.
- **Timestamp-based migrations, not sequential.** Original had 64+ migrations with gaps (094→098, then 112→118; 099-111 missing) from branch conflicts. Use `20260601_001_*.sql`, a schema-version table, and validate sequence on startup. Add migration tests (reversible + idempotent).
- **Coverage 80%+ (95%+ critical paths).** Original ~36%; biggest files had zero dedicated tests. Split pure core lib (no HTTP) from thin handlers; property-test (`proptest`) all validation; test DBs per run.
- **Zero bare TODOs in prod.** 18+ stale TODOs admitted incomplete webhooks/persistence/LLM-synthesis/Vault. Every TODO → tracked issue with link, or delete. CI check to block bare TODOs.
- **Never ship schema before implementation.** Webhooks, email, Confluence export, Drive sync, LLM synthesis all had DB schema but stubbed delivery. "Done" = data survives restart with correct semantics. Use compile-time `#[cfg(feature=...)]` to remove disabled code, not runtime stubs.
- **Pluggable identity from day one.** Discord-only auth (ADR-044 P1-002) blocked all multi-platform work. Ship ≥2 providers behind `dyn IdentityProvider`.
- **Typed failure classification + auto-retry.** No classification (P1-003) blocked auto-retry (P1-004). Use `enum JobFailureReason { Transient, Permanent, UserInput }`; exponential backoff + jitter for transient only.
- **Mandatory audit logging.** Was an afterthought (ADR-044 P2-004, fixed ADR-045). Append-only immutable log; every user-facing endpoint must audit. Test audit completeness.
- **Enforce ownership at the data layer.** Source-ownership not verified (P2-001) — user A could read user B's data. Pass `UserContext` to every repo method; return `None` on denied access. **For the rewrite this escalates to tenant isolation (TEN-007 CRITICAL) enforced at repository layer.**
- **Fail fast, no silent fallbacks.** Silent parameter defaults (P2-002) hid bugs. Invalid param → 400 with explanation. Use newtypes to make invalid states unrepresentable.
- **Correlation IDs everywhere.** No problem-reporting/log correlation (P3-009). Every request gets a UUID returned to the user; use `tracing` spans.
- **UTC always; dedup by platform message ID.** Timezone dedup failures (P3-005) from local timestamps. Normalize to UTC at ingest; dedup on platform message ID, never timestamps.
- **GDPR deletion + soft-delete.** No source deletion (P3-003) = right-to-be-forgotten failure. Soft-delete (`deleted_at`) then verified cascade; audit deletions.
- **Capture all platform mutation events.** WhatsApp edits untracked (P2-005) — only handled create/remove. Build exhaustive event enums (create/edit/delete/react).
- **Short JWTs + refresh tokens.** No immediate revocation (P3-001). 5-15 min access tokens with server-checked refresh-token revocation.
- **Vault/secrets mandatory.** Vault integration was a TODO (backends.py:251). No secrets in code/config/env for prod; validate in CI.

## PRD diff findings

The working `docs/PRD.md` **dropped nothing** from the old PRD-rewrite.md core (§1-12 preserved). The changes are promotions, escalations, and a strategic repositioning:

- **Promotions from Future §13 → committed main sections** (marked ✅ PROMOTED in Appendix D):
  - ADR-066 → §2.4 Platform-Agnostic Workspace Model (WSP-001..008): authenticate without Discord, `workspace_id` replaces `guild_id`, optional cross-platform connections.
  - ADR-079 → §6.3 Multi-Tenancy (TEN-001..007): custom subdomains/domains, branding, member management, **TEN-007 tenant data isolation at repository layer = CRITICAL**.
  - ADR-052 → §8.3 Coherence Gate & Advanced RuVector (COH-001..005): GNN modeling, agent memory, provenance.
  - ADR-077 → §8.4 AI Wiki Curator Agent (CUR-001..007).
- **Priority escalations:** Coherence Gate FUT-020 (Medium/Future) → COH-001 (HIGH/Committed). Wiki curation: proposed → committed.
- **New data models (§7.1):** explicit `Tenant`, `Workspace`, `WorkspaceConnection` structs. Breaking schema migration `guild_id` → `workspace_id` (note: legacy SummaryResult/StoredSummary/ScheduledTask still show `guild_id` for back-compat but WILL migrate).
- **Auth expansion (§6.1-6.3):** Discord-OAuth-only → + email magic link, Google SSO (WSP-001), tenant-scoped OAuth redirects (TEN-006).
- **RuVector roadmap contracted:** only Phase 1 + Coherence Gate committed; agent memory, SONA, rvLite stay future.
- **Terminology:** "Guild" demoted to Discord-adapter internal; "Workspace" is canonical user-facing term.
- **Net:** a strategic pivot from single-platform Discord SaaS to multi-tenant, multi-platform workspace platform — not incremental.

2. ~~**Workspace creation strategy (ADR-066, blocking).**~~ **RESOLVED 2026-06-03: EXPLICIT creation, then connect platforms** (no auto-create on connect). PRD WSP-009.

5. ~~**Cost cap mid-chain failure policy (ADR-024).**~~ **RESOLVED 2026-06-03: best-effort partial, flagged degraded**, with cost+attempt metadata. Cap configurable per-workspace with per-request override. PRD SUM-016.
6. ~~**Quality-detection robustness (ADR-024/025).**~~ **RESOLVED 2026-06-03: structural validation** (response JSON schema + finish_reason), not marker strings. PRD SUM-017.
7. ~~**RuVector scope for v1 (ADR-052/057/087/090).**~~ **RESOLVED 2026-06-03: native Rust crate** (fall back to Rust-native vector lib only if unviable). PRD KNO-006. *Still open*: FTS5 dual-index as a hard launch requirement, and ADR-087→ADR-057 sequencing — defer to Phase 7 detailed design.
8. ~~**Embedding model choice (ADR-052, ADR-090).**~~ **RESOLVED 2026-06-03: local self-hosted** (e.g. bge-small / all-MiniLM via candle), model+version pinned. PRD KNO-007.
